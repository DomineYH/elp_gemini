# 분석 보고서 상세화 설계 (Issue #116)

## 배경

수업 지도안 분석 보고서의 **개선점**·**구체적 제안**이 추상적 일반론("~하면 더 좋다")에 그쳐,
교사가 지도안의 **어느 문구를 어떻게** 고쳐야 하는지 알 수 없다.

요구사항: 보고서를 자세하고 구체적으로. "구체적" = **무엇을 어떻게 수정**(지도안 원문 A → 수정안 B).

## 결정 사항 (사용자 확정)

| 항목 | 결정 |
|---|---|
| 적용 범위 | 1~5번 전 항목 개선점 + 5번 종합 제안 모두 A→B |
| 표기 형식 | 구조화 목록 (`현재 지도안` / `수정 제안` / `수정 근거`) |
| 상세화 수준 | 최대 (분석 8문장+, 항목당 개선점 3개+, 5번 제안 4개+) |

## 변경 대상

- **유일 변경 파일**: `prompt/prompt.md` 의 `## lesson_analysis` 섹션.
- 서비스/라우터/템플릿 코드 변경 **없음**.
  - 근거: 테스트는 `prompt_loader.get_prompt`를 mock 하므로 프롬프트 본문 변경이 단위 테스트를 깨지 않음.
  - 보고서는 마크다운 → 클라이언트 `renderSafeMarkdown()`로 렌더링되므로 구조화 목록이 그대로 표시됨.

## 목표 출력 양식

### 평가 항목 1~4 (각 항목)

```
**분석 내용**
[8문장 이상, 지도안 실제 내용을 근거로 한 구체적 분석]

**근거**
> **평가기준**: [기준]
> **수업지도안**: "[원문 인용]"

**강점**
- [강점 1]
- [강점 2]

**개선점 (현재 → 수정 제안)**

1. **[개선 항목 제목]**
   - 현재 지도안: "[지도안 원문 직접 인용 — A]"
   - 수정 제안: "[구체적으로 다시 쓴 문장/활동 — B]"
   - 수정 근거: [평가기준 관점의 근거]

2. ... (항목당 최소 3개)
```

### 평가 항목 5 (개선 및 보완을 위한 제안)

```
**구체적 제안 (현재 → 수정 제안)**

1. **[제안 제목]**
   - 현재 지도안: "[원문 인용 — A]"
   - 수정 제안: "[구체적 수정문 — B]"
   - 수정 근거: [근거]
   - 기대 효과: [기대 효과]

... (최소 4개)
```

### 강한 지시문 (모델 행동 교정의 핵심)

프롬프트에 다음 규칙을 명시:
- 모든 개선점/제안은 **지도안의 실제 문구를 직접 인용**한 뒤 그것을 어떻게 고칠지 다시 작성.
- "~하면 좋다 / 명시할 필요가 있다" 같은 **추상적 조언 금지**.
- 인용할 원문이 정말 없을 때만 "현재 지도안: (해당 서술 없음)"으로 표기하고 신설 문장을 제안.

## 제약 (반드시 보존)

- 후처리 정규식 마커: `### File Search 평가기준 요약`, `### File Search 참고 문서`, `## 종합 평가`.
- 본문 이모지/픽토그램 금지 (`tests/unit/test_check_no_emojis_in_reports.py`).
- `> **수업지도안**: "..."` 인용 블록 형식 유지 (citation sanitizer가 verbatim 보존).

## 검증 계획

1. `python -m pytest tests/test_prompt_loader_service.py tests/test_lessonplan_analysis_service.py tests/unit/test_check_no_emojis_in_reports.py` → 통과.
2. `ruff check` → 통과 (프롬프트는 .md라 영향 없음, 전체 확인).
3. 후처리 호환: 새 양식 텍스트로 `_post_process_report` 마커 매칭 수동 확인.
4. 베이스라인 대비 신규 실패 0건 (기존 pre-existing 실패는 무관, [[pytest_invocation]] 참고).
