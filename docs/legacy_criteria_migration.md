## 1. 문제 개요

### 무엇이 변경되었나요?
2025년 11월 21일부로 평가기준 관리 시스템이 개선되었습니다.
이제 업로드된 평가기준 문서의 **문서 ID**를 자동으로 저장하여,
삭제 시 문서와 스토어를 순차적으로 정리할 수 있습니다.

### 왜 이런 변경이 필요했나요?
기존 시스템에서는 평가기준을 삭제할 때 다음과 같은 오류가
발생했습니다:

```
400 FAILED_PRECONDITION: Cannot delete a non-empty
FileSearchStore
```

**원인**: 스토어 내부에 문서가 남아있는 상태에서 스토어를
        먼저 삭제하려고 시도했기 때문입니다.

**해결**: 이제 문서를 먼저 삭제한 후 스토어를 삭제하여
        정상적으로 정리됩니다.

### 기존 데이터에 미치는 영향
**2025년 11월 21일 이전**에 업로드된 평가기준은 **문서 ID가
저장되지 않았습니다**.

따라서 이러한 **레거시 데이터**를 삭제하려고 하면 여전히
오류가 발생할 수 있습니다.

## 2. 영향받는 데이터 확인

### 자동 확인 방법
다음 스크립트를 실행하여 레거시 데이터를 확인하세요:

```bash
python scripts/cleanup_legacy_criteria.py --dry-run
```

**출력 예시**:
```
⚠️  총 8개의 레거시 레코드가 발견되었습니다.

[2/3] 삭제 대상 목록:
ID    제목                스토어 ID
2     2022정보교육과정    fileSearchStores/criteriastore-...
4     테스트 문서 1       test_store_1
...
```

### 수동 확인 방법
관리자 대시보드에서 평가기준 목록을 확인하세요.
2025년 11월 21일 이전에 업로드된 항목이 레거시 데이터입니다.

## 3. 해결 방법

두 가지 옵션 중 하나를 선택하세요:

### 옵션 A: 레거시 삭제 후 재업로드 (권장)

**장점**:
- ✅ 완전한 문제 해결
- ✅ 향후 삭제 시 오류 없음
- ✅ 시스템 일관성 확보

**단점**:
- ⚠️ 재업로드 작업 필요
- ⚠️ 일시적으로 평가기준 사용 불가

**추천 대상**: 중요한 평가기준이 많고, 장기적으로 안정적인
              시스템을 원하는 경우

**진행 절차**: [섹션 4](#4-재업로드-절차) 참조

---

### 옵션 B: 자연스러운 교체

**장점**:
- ✅ 즉시 작업 불필요
- ✅ 신규 업로드는 정상 동작
- ✅ 기존 데이터는 계속 사용 가능

**단점**:
- ⚠️ 레거시 데이터 삭제 시 오류 가능
- ⚠️ 장기적으로 데이터 불일치

**추천 대상**: 레거시 데이터를 삭제할 계획이 없거나,
              신규 평가기준으로 자연스럽게 교체할 예정인 경우

**진행 방법**:
1. 아무 작업도 하지 않습니다.
2. 필요할 때 새로운 평가기준을 업로드합니다.
3. 레거시 데이터는 삭제하지 않고 그대로 둡니다.

## 4. 재업로드 절차

### 사전 준비

#### 1. 백업 파일 준비
삭제하기 전에 원본 PDF 파일을 준비하세요.

**백업 위치 확인**:
```bash
ls -la data/uploads/criteria/
```

각 평가기준 파일이 업로드 디렉토리에 있는지 확인합니다.

#### 2. 레거시 데이터 목록 저장
삭제 전에 목록을 저장하세요:

```bash
python scripts/cleanup_legacy_criteria.py --dry-run > \
  legacy_list.txt
```

---

### 단계별 절차

#### Step 1: 레거시 데이터 삭제

**주의**: 이 작업은 되돌릴 수 없습니다. 백업을 먼저 확인하세요!

```bash
# Dry-run으로 최종 확인
python scripts/cleanup_legacy_criteria.py --dry-run

# 실제 삭제 실행
python scripts/cleanup_legacy_criteria.py
```

**확인 프롬프트**:
```
⚠️  경고: DB에서 레코드가 영구 삭제됩니다.
   Google API 리소스(스토어/문서)는 수동으로 정리해야 합니다.

삭제를 진행하시겠습니까? (yes/no):
```

`yes`를 입력하여 진행합니다.

**출력 예시**:
```
✅ 8개 레코드가 삭제되었습니다.

📋 후속 작업:
1. Google API Console에서 스토어/문서 수동 정리 (선택)
2. 필요한 평가기준 재업로드 (본 가이드 참조)
3. 삭제 로그: 2025-11-21T14:30:00
```

---

#### Step 2: 평가기준 재업로드

1. **관리자 대시보드 접속**
   - URL: `http://localhost:8000/admin/dashboard`
   - 관리자 계정으로 로그인

2. **평가기준 업로드 메뉴 선택**
   - 좌측 메뉴에서 "평가기준 관리" → "업로드"

3. **파일 선택 및 업로드**
   - 백업해둔 PDF 파일 선택
   - 제목 입력 (예: "2022 정보교육과정")
   - "업로드" 버튼 클릭

4. **업로드 완료 확인**
   - 성공 메시지 확인: "평가기준이 업로드되었습니다."
   - 평가기준 목록에서 새로 업로드된 항목 확인

5. **반복**
   - 삭제된 모든 평가기준에 대해 2-4단계 반복

---

#### Step 3: 업로드 검증

업로드가 정상적으로 완료되었는지 확인합니다:

```bash
# DB 확인
sqlite3 data/app.db \
  "SELECT id, title, document_id FROM criteria_documents
   ORDER BY id DESC LIMIT 5;"
```

**정상 출력 예시**:
```
19|2022정보교육과정|fileSearchStores/criteria.../documents/...
20|정보|fileSearchStores/criteria.../documents/...
```

**중요**: `document_id` 컬럼에 값이 있어야 정상입니다.

---

#### Step 4: Google API 리소스 정리 (선택)

레거시 스토어를 Google API Console에서 수동으로 삭제할 수
있습니다.

**주의**: 이 단계는 선택사항이며, 건너뛰어도 시스템 동작에
        문제 없습니다.

1. **Google AI Studio 접속**
   - URL: `https://aistudio.google.com/`
   - Google 계정으로 로그인

2. **File Search Stores 메뉴 이동**
   - 좌측 메뉴에서 "File Search Stores" 선택

3. **레거시 스토어 확인**
   - `legacy_list.txt`에 있는 스토어 ID 확인
   - 해당 스토어가 목록에 있는지 확인

4. **수동 삭제**
   - 각 레거시 스토어의 "Delete" 버튼 클릭
   - 삭제 확인

## 5. FAQ

### Q1: 레거시 데이터를 삭제하지 않으면 어떻게 되나요?
**A**: 신규 업로드는 정상 동작합니다. 하지만 레거시 데이터를
     삭제하려고 하면 오류가 발생할 수 있습니다.

---

### Q2: 삭제 스크립트를 실행하면 Google API 리소스도 삭제되나요?
**A**: 아니요. 스크립트는 **DB에서만** 레코드를 삭제합니다.
     Google API 리소스는 수동으로 정리하거나 그대로 둘 수
     있습니다.

---

### Q3: 레거시 데이터 삭제 후 복구할 수 있나요?
**A**: DB 백업이 있다면 복구 가능합니다.
     삭제 전에 백업을 권장합니다:

```bash
cp data/app.db data/backups/app_backup_$(date +%Y%m%d).db
```

---

### Q4: 재업로드 시 기존 설정이 유지되나요?
**A**: 아니요. 재업로드 시 새로운 레코드로 생성됩니다.
     제목이나 활성화 상태는 다시 설정해야 합니다.

---

### Q5: 레거시 데이터를 삭제하지 않고 document_id만 채울 수
       있나요?
**A**: 기술적으로는 가능하지만, Google API 제약으로 인해
     복잡하고 리스크가 높습니다.
     재업로드를 권장합니다.

---

### Q6: 삭제 스크립트 실행 중 오류가 발생하면 어떻게 하나요?
**A**: 다음 단계를 따르세요:
1. 오류 메시지 복사
2. 백업에서 DB 복원
3. 문의 섹션의 연락처로 문의

---

### Q7: 신규 업로드 후에도 오류가 발생합니다.
**A**: 다음을 확인하세요:
1. 업로드가 완전히 완료되었는지 (진행 상태 확인)
2. `document_id`가 DB에 저장되었는지 (Step 3 검증 참조)
3. 브라우저 캐시 삭제 후 재시도

---

### Q8: 여러 개의 평가기준을 한 번에 재업로드할 수 있나요?
**A**: 현재는 하나씩 업로드해야 합니다.
     향후 업데이트에서 일괄 업로드 기능이 추가될 예정입니다.
